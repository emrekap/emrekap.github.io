Work

Nemu 2025–present

Nemu helps a household catalog what it owns, decide together what happens to each thing (keep, pass on, sell, donate), and carry the decision out: shared inventory, pricing help, insurance check, division rounds, a marketplace, exports. Users are largely older, non-technical Americans, so plain language is a design rule.

I rewrote the codebase from scratch and chose the stack: a Bun monorepo; ElysiaJS API with a typed Eden client; Prisma 7 on Postgres (Supabase) with row-level security and triggers; 19 RabbitMQ consumers; Next.js 16 web; Expo SDK 57 on iOS and Android, reusing web views through a shared web-ui package and Expo DOM components; Terraform for AWS; Render, Better Stack, Sentry, PostHog, Stripe; GitHub Actions.

Household assistant

Runs on Claude. Answers "how many items" or "what's in the kitchen" with exact numbers by running structured SQL over indexed columns; I rejected vector search because the questions are COUNT, SUM, and WHERE. It has three tools, kept to three so tool selection stays reliable. Every write is proposal-and-confirm: the model proposes, the user confirms.

Live-scan item capture

On-device detection in the mobile app. I replaced an AGPL-3.0 YOLO-World model with a YOLOX-S detector we own, trained on Hugging Face Jobs from Apache-2.0 base weights. Four releases in three days on about $25 of training; the gain came from the class vocabulary rather than input resolution, and the table has the numbers.

How I use AI

Claude Code is the daily driver. This is how the Nemu repo is set up for it.

The contract
CLAUDE.md is the architecture contract the agent follows: Bun, not Node; the service-class to plugin to handler to route to hook chain that every DB-backed feature takes; exception-to-HTTP-status mapping; branch and release strategy; the WCAG rule.
Skills, committed and evaluated
Repeated work becomes a skill versioned with the code. api-feature-scaffold scaffolds a full feature across the monorepo and ships with an eval suite: 23/23 passes with it, 21/23 without. soc2-policies, policy-review, and policy-export carry the compliance workflow: dashboard, statement-by-statement review, .docx export.
Spec, then plan, then code
I commit design specs and implementation plans to docs/superpowers before code. August 2026 had six of each, among them live-scan capture, the household assistant, SFTP ingest, and a legacy-model-to-service conversion.
Memory
A file-based memory of decisions and corrections carries across sessions. Entries read like "never overwrite a shipped detector", "no git stash for verification", "users are older and non-technical, plain language everywhere".
Parallel agents
Independent tasks in isolated git worktrees; multi-agent workflows for research, design panels, and adversarial review.
Gates and hooks
A code-discovery gate makes the agent query a code knowledge graph before it greps. A "ponytail" plugin enforces a lazy-senior-dev ladder: does this need to exist, is it already here, does stdlib or the platform do it, can it be one line, only then write code. Every commit passes lint-staged via husky; no --no-verify.
MCP
Drata, Render, Sentry, PostHog, Supabase, Prisma, Stripe, Semgrep, Hugging Face, Runpod, AWS pricing, and Figma are wired in over MCP.
Work done this way
The SOC 2 policies above were drafted, reviewed one statement at a time, and uploaded through the Drata API. The AWS control remediation went into Terraform the same way. So did the detector: trained, exported, and gated through agent-driven Hugging Face jobs, with me as the quality gate.
